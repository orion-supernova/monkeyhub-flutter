UI Architecture Handbook

How MonkeyHub shares one codebase across iOS, Android, web, macOS, Windows and Linux, and how it swaps whole control families (Liquid Glass, Frosted, Lite, Material) from one setting. Read §1 and the §10 checklist before adding any screen, control or platform branch.

1. The rules

R1 One widget per role. A back button is GlassBackButton, everywhere: pages, sheets, viewers, games, the fight screens. If a role exists in the catalog, use it. If it almost fits, add a parameter to it. Never write a private _BackButton, _Chip or _Pill.
R2 Behaviour once, pixels per kit. A shared component owns semantics, focus, hover hint, keyboard shortcut, haptic, disabled state and tap target. Only the paint is swapped per kit, through KitSwitch / kitValue. A fix to behaviour lands in one place and every kit gets it.
R3 Ask Caps, by intent. No Platform.isX, defaultTargetPlatform or kIsWeb in UI code. Ask Caps.hover, Caps.physicalKeyboard, Caps.mobileCalls. A new intent is a new getter in lib/ui/foundation/caps.dart, documented with who is in and who is out, web included.
R4 Layout follows the window, not the OS. Phone vs split shell is context.usesSplitShell / context.windowClass. A screen body is written once and placed by the shell. No magic-number widths: add a constant to Breakpoints.
R5 Theme tokens only. No hard-coded colours in shared chrome. Light/dark is theme.isLight. Plates use plateFill / plateEdge.
R6 Never animate a blur, never fade glass. Glass grows in (GlassReveal); a moving surface is still. Every BackdropFilter outside LiquidGlass must check UiKit.of(context).blurs.
R7 Motion through MotionScope. Never read MediaQuery.disableAnimations directly: it ignores the user's Calm/Full override.
R8 No ink. No InkWell, ripples or Material buttons. Tappables are SpringPress (or FocusableTap for a bare row). Never wrap a GestureDetector(onTap) inside a FocusableTap(onTap) with the same callback.
R9 44pt targets. Every tappable is at least 44×44 logical pixels on touch, even when the visual is smaller (pad the hit area, not the glyph). Density may shrink desktop controls.
R10 Format once. Durations, "x ago", day labels, byte sizes, initials and room titles come from the shared modules in §7, never a private _fmt.

What the audit found (2026-11-06)

  • ~510 platform-check lines in ~170 files; the "kIsWeb first" dance repeated ~120 times.
  • "Desktop" meant three different things. isWebOrDesktop was used as "has hover" in ~30 places, which gave phone browsers desktop viewer chrome. Those move to Caps.hover.
  • The mobile-call predicate was copied 6 times (call_media, call_service, group_call_service, call_pip, draw_mirror, capture_compose); app.dart had one iOS/Android function twice.
  • Platform channels: monkeyhub/device declared in 8 files, voip in 4, haptics in 3. Target: one Dart bridge class per channel name, under lib/ui/native/ or the owning feature folder.
  • 14 conditional-import barrels key on dart.library.html, which resolves to the io twin under WASM. Standard: if (dart.library.js_interop), files named *_io.dart / *_web.dart.

4. UI kits

UiKit.glass
Frosted

MonkeyHub's own glass. The reference kit: every other kit falls back to it, component by component.

UiKit.liquid
Liquid Glass

iOS 26+. Native UITabBar as a sibling view; app glass uses the native-matched recipe.

UiKit.lite
Lite

No backdrop blur, opaque plates, no drop shadows. Auto on low-RAM phones. Offered everywhere.

UiKit.material
Material

Android. Not built: UiKits.materialReady = false, so never offered or resolved.

Resolution

SettingsStore.uiKit   (null = Automatic, persisted as 'mh.ui.kit')
      │  UiKits.resolve(choice)          lib/ui/foundation/ui_kit.dart
      ▼
choice available on this device?  → that kit
else Caps.nativeGlass             → liquid
else Perf.low (RAM < 3600 MB)     → lite
else android && materialReady     → material
else                              → glass
      │
      ▼
UiKitScope (above MaterialApp in app.dart)  →  UiKit.of(context)

A choice the device cannot honour (Liquid Glass on Android) quietly means Automatic, so a synced or restored setting never breaks a device. The old mh.glass.engine = 'flutter' migrates to an explicit Frosted; the old default (native) migrates to Automatic, which resolves to the same thing.

Settings › Glass › Style shows Automatic plus UiKits.offered. The glass dials only show under Frosted. Settings' Glass row names the active kit.

Writing a kit-aware component

class GlassIconButton extends StatelessWidget {
  // Behaviour: semantics, HoverHint, shortcut, haptic, disabled, 44pt target.
  @override
  Widget build(BuildContext context) => HoverHint(
    label: semanticLabel, shortcut: shortcut, enabled: onTap != null,
    child: SpringPress(
      onTap: onTap, semanticLabel: semanticLabel,
      builder: (context, pressed) => KitSwitch(
        glass: (context) => _GlassDisc(pressed: pressed, …),   // required: the reference
        lite: (context) => _PlateDisc(pressed: pressed, …),    // optional
        // liquid, material: fall back to glass until they have a skin
      ),
    ),
  );
}

// Values, not widgets:
final radius = kitValue(UiKit.of(context), glass: 22.0, material: 16.0);

Most components need no KitSwitch at all today: they paint with LiquidGlass, and LiquidGlass already draws all three live kits. Add a skin only when a kit needs a different SHAPE or structure (Material's filled tonal button, a native UISwitch).

Adding a kit (the iOS 26 native controls, the Android library)

  1. Implement skins for the core set first: surface (LiquidGlass), icon button, primary/secondary button, text field, search field, switch, segmented control, chip. Everything else falls back to glass meanwhile.
  2. Flip the availability flag in UiKits.available (materialReady) and add the row to the chooser in glass_screen.dart (plus ARB strings via tool/arb_add.py).
  3. Render every theme with the kit pinned (UiKitScope(kit: …) in a design preview) and look at the PNGs.
  4. Native views: never put a UiKitView inside a scrolling list (drops 120 Hz to 60 Hz and doubles BackdropFilter cost). Native controls go in as siblings over the Flutter view (the NativeChrome tab-bar pattern) or are matched in Flutter (the kNativeMatchGlass recipe). A per-control platform view is acceptable only for a control that is alone on a static screen.
  5. Third-party Android library: wrap it inside the material skin of each component. Screens never import it directly. If the library's widgets cannot take our tap/semantics wrapper, wrap them, not the reverse.

6. Layout: phone, tablet, desktop

  • lib/theme/layout.dart: Breakpoints.medium = 600, split = 720, expanded = 1024; WindowClass published once by LayoutScope; read context.usesSplitShell, context.isCompact, context.windowClass.
  • The shell forks, bodies don't. HomeShell picks phone (bottom bar: native or pill) or split (side rail + ListDetailSplit + RoomSidePane). The chat list, the room, settings pages are the same widgets in both.
  • Back vs ×: GlassBackButton decides by itself (× on the split shell at depth 1).
  • Sheets: showAdaptiveSheet is a bottom sheet on compact and a floating panel on wider windows.
  • Viewer chrome (always-visible vs tap-to-toggle) keys off Caps.hover, not off "web or desktop".
  • Known magic numbers to fold into Breakpoints: fight lobby 860/460, media pager 700, game start sheet 560/420, bot hub 700/480, device_turn 600, swipe_to_reply 430.

10. Checklist for new work

  1. Is the role in the catalog? Use it. Missing a parameter? Add it there.
  2. No Platform/kIsWeb/defaultTargetPlatform outside lib/ui/foundation and OS bridges. Ask Caps.
  3. No colour literals in chrome; light/dark via theme.isLight.
  4. Any BackdropFilter? Prefer LiquidGlass. Otherwise gate it on UiKit.of(context).blurs and never animate it.
  5. Any motion? MotionScope.of(context); kicks per chrome-language; moments only for real moments.
  6. Tap target ≥ 44pt; semantics label; disabled = null onTap; no ink.
  7. Strings through python3 tool/arb_add.py (all 12 locales, no em dashes in UI text).
  8. Layout via context.usesSplitShell/windowClass; body written once.
  9. Formatting via §7 helpers.
  10. Render a PNG (design preview) in each kit you touched before calling it done.
  11. Never dart format (hand-formatted repo). Run only the tests you touched.

11. Decisions log

  • 2026-11-06 GlassEngine {native, flutter} generalized into UiKit with an Automatic default. Liquid Glass loses its "Recommended" tag; Automatic picks it on iOS 26.
  • 2026-11-06 Low-RAM phones (< 3600 MB, the iPhone 8/XR/SE 2 class and 3 GB Android) resolve to Lite under Automatic. iOS 26 devices stay on Liquid Glass even when low-RAM: the OS draws that glass.
  • 2026-11-06 Low Power Mode keeps calming motion only. It does not switch kits: a whole-UI change on a battery threshold would be jarring.
  • 2026-11-06 Components keep their existing names (GlassIconButton etc.) rather than a mass rename to App*: the names are in memory, docs and graphify, and the kit layer works under them. The catalog is the index.
  • 2026-11-06 Both message leave animations stay: vanish burn for ephemeral rooms, delete exit for deletes.
  • 2026-10-02 Native glass is a sibling UITabBar, never a platform view in Flutter content (performance).
