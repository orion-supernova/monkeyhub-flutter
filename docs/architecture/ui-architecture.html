UI Architecture Handbook

How MonkeyHub shares one codebase across iOS, Android, web, macOS, Windows and Linux, and how it swaps whole control families (Liquid Glass, Frosted, Lite, Material) from one setting. Read §1 and the §10 checklist before adding any screen, control or platform branch.

Started 2026-11-06. Code is the source of truth. When this page and the code disagree, fix this page in the same commit.

1. The rules

R1 One widget per role. A back button is GlassBackButton, everywhere: pages, sheets, viewers, games, the fight screens. If a role exists in the catalog, use it. If it almost fits, add a parameter to it. Never write a private _BackButton, _Chip or _Pill.
R2 Behaviour once, pixels per kit. A shared component owns semantics, focus, hover hint, keyboard shortcut, haptic, disabled state and tap target. Only the paint is swapped per kit, through KitSwitch / kitValue. A fix to behaviour lands in one place and every kit gets it.
R3 Ask Caps, by intent. No Platform.isX, defaultTargetPlatform or kIsWeb in UI code. Ask Caps.hover, Caps.physicalKeyboard, Caps.mobileCalls. A new intent is a new getter in lib/ui/foundation/caps.dart, documented with who is in and who is out, web included.
R4 Layout follows the window, not the OS. Phone vs split shell is context.usesSplitShell / context.windowClass. A screen body is written once and placed by the shell. No magic-number widths: add a constant to Breakpoints.
R5 Theme tokens only. No hard-coded colours in shared chrome. Light/dark is theme.isLight. Plates use plateFill / plateEdge.
R6 Never animate a blur, never fade glass. Glass grows in (GlassReveal); a moving surface is still. Every BackdropFilter outside LiquidGlass must check UiKit.of(context).blurs.
R7 Motion through MotionScope. Never read MediaQuery.disableAnimations directly: it ignores the user's Calm/Full override.
R8 No ink. No InkWell, ripples or Material buttons, except inside a material: skin of the Material kit (approved 2026-11-07), which wraps itself in MaterialKitScope. Tappables are SpringPress (or FocusableTap for a bare row). Never wrap a GestureDetector(onTap) inside a FocusableTap(onTap) with the same callback.
R9 44pt targets. Every tappable is at least 44×44 logical pixels on touch, even when the visual is smaller (pad the hit area, not the glyph). Density may shrink desktop controls.
R10 Format once. Durations, "x ago", day labels, byte sizes, initials and room titles come from the shared modules in §7, never a private _fmt.

3. Platform seam: Caps

lib/ui/foundation/caps.dart. Every platform question is a getter named for what the caller wants. The legacy lib/platform.dart (isWebOrDesktop, isPhysicalKeyboardPlatform) is gone; every caller moved. Platform channel names live once in lib/ui/foundation/channels.dart (Channels.device, voip, haptics, installer, callWindow, window, share).

Testing note: Caps reads defaultTargetPlatform, which is android under flutter_test (the old Platform.isX read the Mac host). Mobile-only native paths are therefore live in tests: test/flutter_test_config.dart stubs the push inbox, and a test about desktop behaviour sets debugDefaultTargetPlatformOverride.

What the audit found (2026-11-06)

  • ~510 platform-check lines in ~170 files; the "kIsWeb first" dance repeated ~120 times.
  • "Desktop" meant three different things. isWebOrDesktop was used as "has hover" in ~30 places, which gave phone browsers desktop viewer chrome. Those move to Caps.hover.
  • The mobile-call predicate was copied 6 times (call_media, call_service, group_call_service, call_pip, draw_mirror, capture_compose); app.dart had one iOS/Android function twice.
  • Platform channels: monkeyhub/device declared in 8 files, voip in 4, haptics in 3. Target: one Dart bridge class per channel name, under lib/ui/native/ or the owning feature folder.
  • 14 conditional-import barrels key on dart.library.html, which resolves to the io twin under WASM. Standard: if (dart.library.js_interop), files named *_io.dart / *_web.dart.

4. UI kits

UiKit.glass
Frosted

MonkeyHub's own glass. The reference kit: every other kit falls back to it, component by component.

UiKit.liquid
Liquid Glass

iOS 26+. Native UITabBar as a sibling view; app glass uses the native-matched recipe.

UiKit.lite
Lite

No backdrop blur, opaque plates, no drop shadows. Auto on low-RAM phones. Offered everywhere.

UiKit.material
Material

Built (2026-11-07): Flutter's Material 3 widgets dressed from the current AppTheme (lib/ui/kits/material/). Offered on phones and tablets (Caps.nativeMobile: Android, and iOS "just for fun" since 2026-11-07), never on web or desktop. Automatic gives it to Android only, unless the phone is low-RAM (then Lite). The one kit with ripples.

UiKit.shader
Shader glass

Added 2026-11-07 at the user's request. Glass drawn by the vendored liquid_glass_widgets GPU shader engine (third_party/liquid_glass_widgets, skin in lib/ui/kits/shader/): a real lens with refraction and a lit rim, in the package's iOS 27 optics (ios27Light / ios27Dark by page brightness, Swirl's "clear native" recipe, so it reads as clear refracting glass, not frost). Every shared component wears the package's own widget (see the skin list below). Android and iOS only (Caps.nativeMobile), never web or desktop, never chosen by Automatic. If the shader cannot start, UiKits.shaderUsable flips off and the app is drawn as Frosted. Falls back to glass component by component.

Resolution

A choice the device cannot honour (Liquid Glass on Android) quietly means Automatic, so a synced or restored setting never breaks a device. The old mh.glass.engine = 'flutter' migrates to an explicit Frosted; the old default (native) migrates to Automatic, which resolves to the same thing.

Settings › Glass › Style shows Automatic plus UiKits.offered. The glass dials only show under Frosted. Settings' Glass row names the active kit. Under Shader glass the Frosted dials give way to the engine's own (thickness, blur, refraction, chromatic aberration, light intensity and angle, rim light, saturation, tint, plus a full-lens switch), kept in SettingsStore.shaderGlass (mh.glass.shader, a sparse JSON map of the dials moved off standard; lib/data/shader_glass_config.dart). The dials map onto the iOS 27 preset (ShaderGlassConfig.settings): a dial at standard leaves the preset alone; moved, thickness, blur (as frost), tint, rim and saturation scale it, and refraction, chromatic aberration, light intensity and angle replace its value. Under Liquid Glass and Shader glass, Settings › Glass also shows Interactive glass (SettingsStore.glassInteractive, mh.glass.interactive, default on): the press jelly, stretch and glow. Off, the shader kit's buttons, tab bar, switch, slider and segmented control press without scaling, stretching or glowing (ShaderSkin.themed sets the package theme's GlassInteractionSettings).

The shader kit's performance contract

  • Default quality is the library's lightweight shader: one backdrop filter plus a small fragment pass per surface, every surface its own layer. The premium multi-pass lens (real refraction of a captured backdrop) is the user's "Full lens refraction" switch, off by default, and is forced back to lightweight on Perf.low and while LowPowerMode.active. Chromatic aberration is dropped in the same cases. Exception (ShaderSkin.heroQuality): the bottom tab bar, switch, slider and segmented control take the premium lens on every device that is not low-tier or saving power. The tab bar is one surface per screen; the switch and slider mount their shader only while pressed or dragged (the package's own rule). Everything else stays lightweight.
  • Shaders are warmed once (ShaderGlassEngine.ensureStarted): at launch only if the saved kit is Shader glass, otherwise the first time one is built or chosen. Nothing loads for anyone on another kit.
  • Media-tone glass (over photos and video) keeps its own dark recipe in this kit; only app glass is shader-drawn. The generic LiquidGlass surface picks the iOS 27 clear recipe with no per-component work.
  • Safety: a failed start calls ShaderGlassEngine.markFailed, which makes the kit unavailable so the app resolves to Frosted; a shader that fails per surface falls back to the library's frosted fallback. Under flutter test the pre-warm is skipped (the library looks for its shaders where a package under test has them, not where an app does) and surfaces still build.

Writing a kit-aware component

class GlassIconButton extends StatelessWidget {
  // Behaviour: semantics, HoverHint, shortcut, haptic, disabled, 44pt target.
  @override
  Widget build(BuildContext context) => HoverHint(
    label: semanticLabel, shortcut: shortcut, enabled: onTap != null,
    child: SpringPress(
      onTap: onTap, semanticLabel: semanticLabel,
      builder: (context, pressed) => KitSwitch(
        glass: (context) => _GlassDisc(pressed: pressed, …),   // required: the reference
        lite: (context) => _PlateDisc(pressed: pressed, …),    // optional
        // liquid, material: fall back to glass until they have a skin
      ),
    ),
  );
}

// Values, not widgets:
final radius = kitValue(UiKit.of(context), glass: 22.0, material: 16.0);

Most components need no KitSwitch at all today: they paint with LiquidGlass, and LiquidGlass already draws all three live kits. Add a skin only when a kit needs a different SHAPE or structure (Material's filled tonal button, a native UISwitch).

Adding a kit (the iOS 26 native controls, the Android library)

  1. Implement skins for the core set first: surface (LiquidGlass), icon button, primary/secondary button, text field, search field, switch, segmented control, chip. Everything else falls back to glass meanwhile.
  2. Flip the availability flag in UiKits.available (materialReady) and add the row to the chooser in glass_screen.dart (plus ARB strings via tool/arb_add.py).
  3. Render every theme with the kit pinned (UiKitScope(kit: …) in a design preview) and look at the PNGs.
  4. Native views: never put a UiKitView inside a scrolling list (drops 120 Hz to 60 Hz and doubles BackdropFilter cost). Native controls go in as siblings over the Flutter view (the NativeChrome tab-bar pattern) or are matched in Flutter (the kNativeMatchGlass recipe). A per-control platform view is acceptable only for a control that is alone on a static screen.
  5. Third-party Android library: wrap it inside the material skin of each component. Screens never import it directly. If the library's widgets cannot take our tap/semantics wrapper, wrap them, not the reverse.

The liquid kit's native controls

Real SwiftUI controls in ONE overlay view above the Flutter view (NativeOverlay in ios/Runner/NativeControls.swift, channel monkeyhub/native_overlay), never platform views. Why: Flutter clips a platform view with a mask view whenever any ancestor clips (every scroll view does), and a masked Liquid Glass view renders offscreen as a flat grey rectangle: the "cut-outs" of 1.3.143/144 (lab rows, chat header, call pair). Swirl's NativeGlassOverlay settled the same question the same way. Dart (NativeControl + the NativeOverlay bridge in lib/ui/native/native_control.dart) sends each control's NativeSpec (set), and after every frame one batched sync with every control's rect, its visible clip and whether it may show; events come back as event {id, name, value} (tap / changed / changeEnd / submitted / select / focus / size / revealed).

  • Visible clip: the control's rect cut by every clipping render ancestor (viewports, ClipRect/RRect/Path/Oval, so collapsing AnimatedSizes too) and at the page bar line published by NativeCut (which no longer clips Flutter content: the soft edge is back in every kit). A plain clipsToBounds ancestor cuts pixels and leaves the glass live.
  • Hidden (clip to nothing, never alpha: alpha does not fade Liquid Glass) when its route is not current or is animating, its ticker is off (offstage tab), an ancestor has opacity under 0.05 or is offstage, or NativeOverlay.suppress() is held by a Flutter overlay drawn above. While hidden, standIn shows: the component's own build under FlutterSkinsOnly (FlutterSkinsOnly(child: Builder(builder: build)), never the widget itself, which would duplicate a GlobalKey).
  • Chat chrome: titlePill (avatar from the image disk cache via nativeImageFile, name, status line) and pinBar kinds draw the compact room header's capsule and pinned bar natively; filter chips are native capsules.
  • Native sheets: showNativeActionSheet presents the system action sheet / alert (glass on iOS 26). showConfirmSheet(Choice) uses it under native controls. Sheets with Flutter content (forms like the mute sheet) cannot be native without a second engine and stay Flutter.
  • Interactive glass (SettingsStore.glassInteractive) goes over as interactive and drives .glassEffect(.regular.interactive(…)).
  • Headless simulator checks: --dart-define=OPEN_LAB=true LAB_SECTION=0-3, OPEN_ROOM=<n or name>, CHAT_STYLE=compact|classic, NATIVE_CONTROLS=true, UI_KIT=<kit>.

Components opt in with liquid: NativeControl.ready ? _liquid : null in their KitSwitch, so everything falls back to glass when the scope is "just the tab bar", the device is not iOS 26, or a control has no exact native form (an icon without an SF Symbol in sfSymbolFor, a segment with a badge, a busy button).

  • The scope setting replaces the old nativeControlsReady flag: Settings › Glass › Native controls (shown under Liquid Glass only) is SettingsStore.nativeScope, NativeScope.everything or NativeScope.tabBar (default: just the tab bar until a device pass). UiKits.nativeControls reads it; NativeControl.readyIn(context) is the one question components ask. Settings › Glass › Controls lab (lib/ui/lab/controls_lab_screen.dart, also --dart-define=OPEN_LAB=true) lists every shared control in the active kit for review and screenshots.
  • Covered components (each keeps its behaviour, adds a native skin when it has an exact native form): GlassIconButton / back / close (symbol button), GlassButtonGroup (one native capsule when every slot is a plain symbol), GlassPillButton and RowPillButton (labelled glass button), ThemedInput / SheetTextField / PasswordField (single-line field, secure for passwords; synced through NativeTextInput: typing never echoes back, an outside controller edit bumps textRev, FocusNode and the native first responder mirror each other), SearchField (plain mode), PullDownButton (a SwiftUI Menu: the glass button morphs into the system menu), RowSwitch, IosSegmentedControl, ValueSlider, SheetActionButton, the compose sheet's date-and-time wheel (datePicker, wheel), ViewerToolbar (native discs plus a capsule), CallGlyphButton and CallButtonPair (the chat header's video and voice buttons: two separate discs in one GlassEffectContainer, so they merge like the iOS 26 toolbar; toolbar takes spacing and blend), QuickActionTile / SheetQuickActions (tile, added 2026-11-08: a symbol over a two-line label on an interactive rounded glass plate; the Flutter face is laid out invisibly to decide the size, so a row stays one equal-height band, and the NativeControl fills it; Flutter twin is ChromeDisc.plate).
  • Events must ask for a frame. A native control changes nothing in Flutter's tree, so no frame follows its event. A handler that defers to the next frame (addPostFrameCallback, as IosSegmentedControl commits) then waited for an unrelated redraw: the Calls filter lagged 1 s+ (2026-11-08). NativeControl._event now calls ensureVisualUpdate() after every event. Any other platform channel that defers work must do the same. See docs/lessons.md L1.
  • Adding a kind: NativeSpec.<kind> (Dart) + a case in NativeControlRoot and a view in NativeControls.swift; give rounded kinds a dimRadius case; map every icon in _symbols; add the component to the Controls lab; typecheck Swift at deployment target 15.0 (xcrun --sdk iphonesimulator swiftc -typecheck -target arm64-apple-ios15.0-simulator -F <Flutter.xcframework sim slice> ios/Runner/NativeControls.swift). A Swift change needs a full flutter run.
  • What stays Flutter, and why: sheets with Flutter content (a native sheet would need a second engine; choice and confirm sheets are native, above); the hold / long-press menus (showMessageActionMenu, showChatRowActionMenu, and the row-anchored showPullDownMenu callers in Calls and Data & Storage: they lift a Flutter preview or anchor to a row, not to a button); multi-line fields and fields with a character limit, a trailing widget or a custom fill; a lit or text or drawn-glyph slot in a button group; a busy or badged button; a search field with a scope tag, hero flight or custom clear; ScheduleTimePicker (5-minute steps and a moving floor and ceiling that DatePicker cannot express); the busy call buttons (they dim and still answer a tap). Media-tone glass over photos stays Flutter.
  • Cost: no platform views, so lists keep 120 Hz. The overlay follows scrolling from Dart's post-frame sync, which can trail Flutter by a frame on a fast fling; check on device.
  • Carried lessons from the React Native port (monkeyhub-reactnative/docs/native-ui.md): hosts ignore the safe area; a slider never gets a zero step; a menu label takes buttonStyle(.glass); chrome buttons are 44 pt with a 17 pt symbol.
  • The Flutter-drawn "native-matched" glass (kNativeMatchGlass) still paints app glass under the liquid kit. A separate glass library will become its own option later (user, 2026-11-07); no further Flutter imitation of iOS controls is planned.

10. Checklist for new work

  1. Is the role in the catalog? Use it. Missing a parameter? Add it there.
  2. No Platform/kIsWeb/defaultTargetPlatform outside lib/ui/foundation and OS bridges. Ask Caps.
  3. No colour literals in chrome; light/dark via theme.isLight.
  4. Any BackdropFilter? Prefer LiquidGlass. Otherwise gate it on UiKit.of(context).blurs and never animate it.
  5. Any motion? MotionScope.of(context); kicks per chrome-language; moments only for real moments.
  6. Tap target ≥ 44pt; semantics label; disabled = null onTap; no ink.
  7. Strings through python3 tool/arb_add.py (all 12 locales, no em dashes in UI text).
  8. Layout via context.usesSplitShell/windowClass; body written once.
  9. Formatting via §7 helpers.
  10. Render a PNG (design preview) in each kit you touched before calling it done.
  11. Never dart format (hand-formatted repo). Run only the tests you touched.

11. Decisions log

  • 2026-11-06 GlassEngine {native, flutter} generalized into UiKit with an Automatic default. Liquid Glass loses its "Recommended" tag; Automatic picks it on iOS 26.
  • 2026-11-06 Low-RAM phones (< 3600 MB, the iPhone 8/XR/SE 2 class and 3 GB Android) resolve to Lite under Automatic. iOS 26 devices stay on Liquid Glass even when low-RAM: the OS draws that glass.
  • 2026-11-06 Low Power Mode keeps calming motion only. It does not switch kits: a whole-UI change on a battery threshold would be jarring.
  • 2026-11-06 Components keep their existing names (GlassIconButton etc.) rather than a mass rename to App*: the names are in memory, docs and graphify, and the kit layer works under them. The catalog is the index.
  • 2026-11-06 Both message leave animations stay: vanish burn for ephemeral rooms, delete exit for deletes.
  • 2026-11-07 formatClockDuration shows 1:02:03 past an hour (was 62:03); companion and transcript downloads of 1 GB or more read "2.4 GB" (was "2457 MB").
  • 2026-11-07 Viewer and hover chrome follow Caps.hover: phone browsers get the touch chrome.
  • 2026-11-07 Fight sheets and buttons follow the app theme and the shared buttons (44pt), no longer a fixed dark panel.
  • 2026-11-07 Ripples (InkWell, InkRipple) are allowed inside the Material kit ONLY, approved by the user; the rest of the app stays ink-free (NoSplash in the app theme). The kit's Theme (MaterialKitTheme, cached per AppTheme) supplies the splash.
  • 2026-11-07 Android look = Flutter's built-in Material 3 widgets, not native Android views: same rendering pipeline, no platform-view cost in lists, themed from AppTheme so all palettes survive.
  • 2026-11-07 Added UiKit.shader ("Shader glass") at the user's request: the liquid_glass_widgets engine as an extra, explicit-opt-in glass option on Android and iOS only. Named for what it is (a GPU shader) rather than "Liquid Glass", which is Apple's name for the iOS 26 kit. Kept as an addition: Frosted, Liquid Glass, Material and Lite are unchanged. Not picked by Automatic because per-surface shader glass costs more GPU than Frosted; the premium lens is a second opt-in inside it. Desktop and web are excluded because the pipeline is tuned for mobile GPUs and the library caps itself there anyway.
  • 2026-11-07 The shader kit uses the package's own widgets for every control, in iOS 27 optics by page brightness, copying Swirl's package_glass.dart ("clear native") approach. The app keeps owning behaviour (haptics, hover hints, commit rules, semantics); the package owns the pixels and the press effects. The tab bar, switch, slider and segmented control take the premium lens (not behind the Full lens switch) because there is one per screen or they mount their shader only while held; everything else stays lightweight. Material is also offered on iOS. The only patch beyond Swirl's pill widths is a MonkeyHub one on GlassTextField (text input knobs).
  • 2026-10-02 Native glass is a sibling UITabBar, never a platform view in Flutter content (performance).
