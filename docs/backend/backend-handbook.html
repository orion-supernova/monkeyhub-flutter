Layers every function goes through

Authenticationfunctions.tsEvery public query/mutation/action resolves the session and overwrites userId (or the named identity arg) with the caller. Unauthenticated entry points are spelled public* and allowlisted by a test.
Write hooksdbHooks.tsEvery mutation (public and internal) gets a wrapped ctx.db. Writes to hooked tables update derived rows in the same transaction. Today: messages → roomContentCounts. A test fails if a file imports a mutation builder from _generated/server.

4. Rules (the checklist)

Every backend change is checked against these. A design that breaks one needs a written reason in the PR or commit.

Subscriptions

R1. A subscription must not read a document that is written for bookkeeping.Convex re-runs a query when any document or index range it read changes. Receipts, delivery cursors, typing timestamps, rate buckets and engagement rows belong in side tables that only the screens that display them read.
R2. Never read a whole users row in a subscription.Read profiles for name/handle/photo and presence (via presenceApi:forUsers) for status. A users read couples your screen to every profile edit and presence write.
R3. Scope subscriptions to what is on screen.Pass the visible ids (rooms, people) as arguments; cap them (about 100). No session-long "everything about me" queries that re-run for off-screen data.
R4. Every read in a subscription is index-ranged and bounded..take(n) or a range with both ends. No .collect() on anything that grows with time, friends or members. Expired rows must be outside the range, not filtered after reading.
R5. A client write must not re-run the writer's own subscriptions unless the screen changes.The delivery report currently re-runs the chat list that triggered it. Check the echo of every write you add.
R6. Return only what the screen renders.Spreading a whole document into a result ships every new field to every subscriber on every re-run.
R7. The app pauses non-visible subscriptions when backgrounded.Typing and the list keep re-running for a hidden app until the OS suspends the socket.

Writes

R8. Keep derived numbers current at write time; never compute them on open.Counts, unread, badges: one small row updated in the same transaction (the roomContentCounts pattern). A full scan is allowed only as a one-off backfill.
R9. Route derived-data upkeep through dbHooks.tsso no write path can forget it, and add a test that pins the behaviour.
R10. Never rewrite a growing array.Patch rewrites the whole document. Arrays inside hot documents stay small (about 20 entries) or move to rows.
R11. Shared documents are not touched by per-recipient work.A mutation that runs once per recipient or per device must not read or write the room document (that is what makes markDeliveredByPush conflict).
R12. No per-message scheduled jobs, no new crons for work an event can do.Range jobs and self-rescheduling sweeps only; idle cost is one index probe.
R13. Every new index is justified by a read path.Each index is a write on every insert and every patch that touches its fields. messages already has 14.

Data lifecycle

R14. Every table has a growth story.Either bounded by its parent (cascade), or swept by retention, or explicitly "kept forever" with a reason. New tables need a reference rule (enforced by test) and a retention line in this doc.
R15. Files are released through refs, never deleted by hand.
R16. Whole-history work is batched.Anything that walks a user's or room's history goes through the deletion engine or a sweep, not one transaction.

Process

R17. Every design comes with a cost table:reads and writes per action, re-runs it causes per recipient, and the idle cost, before vs after. Use section 5's budgets as the bar.
R18. Measure after deploywith the log script in section 8, and compare with the before numbers.
R19. Breaking changes are fine while testers-only, but every cutover has a minimum version and a removal step.After store launch, compatibility is mandatory.

6. Improvement plan

Ordered by load saved per unit of effort. Each phase ships on its own; backend first, app second. Evidence is file:line in backend/convex unless noted.

Phase A: switches and settings (minutes, no code)

A1. Turn off the presence compat mirror

verifiedserver-only
Now
PRESENCE_COMPAT_MIRROR is unset in production, so the mirror is on (presenceCore.ts:41). Every status change, and every 5 minutes while online, it patches users.status/lastSeen, which re-runs every friend's listFriends, guardians' getFamilyContext, getMembers and feed:board.
Change
npx convex env set PRESENCE_COMPAT_MIRROR off. The minimum supported app is 1.3.137, which reads presence through presenceApi. Only the stale home server still needs the old path, and it is unreachable anyway.
Saves
The largest remaining cross-user invalidation source. estimate friend-list and family re-runs drop ~70%.

A2. Finish the file-reaper rollout

verifiedserver-only
Now
FILE_REFS_REAP and FILE_REFS_ENFORCE are unset. The Phase 3 runbook's step 7 was due 2026-10-24, so orphaned files have not been deleted since and disk only grows.
Change
Follow the runbook in the plan's Phase 3 status: re-run the zero-ref report, then set FILE_REFS_REAP=1, a week later FILE_REFS_ENFORCE=1.
Saves
Disk and backup size; no CPU change.

A3. Cloudflare caches stored files, purged the moment one is deleted

verifiedserver-onlydecided 2026-11-06
Now
private, max-age=2592000 and cf-cache-status: DYNAMIC: every new device downloads every file from the box through the tunnel.
Change
(1) A Cloudflare Cache Rule for termio-api.walhallaa.com/api/storage/*: eligible for cache, edge TTL 30 days, ignoring the origin's private. If Cloudflare won't override private on this plan, a Caddy header rule on the same path sends public, max-age=2592000, immutable instead. Storage ids are unique per upload, so a URL's content never changes. (2) Purge on delete: every path that deletes a stored file (releaseRowFiles, the reaper, account and room deletion through the engine) enqueues the file's URL in a small cdnPurges table. A self-rescheduling action drains it in batches of 30 through Cloudflare's purge-by-URL API. Because it rides the same file-release path, nothing can delete a file without purging it (R9, R15). View-once media keeps its own no-store route and is never cached.
Privacy
A deleted file leaves Cloudflare's edge within seconds of the delete, not at expiry. The purge queue retries until Cloudflare confirms, and the integrity check flags any queue row older than an hour.
Setup (once)
In the Cloudflare dashboard: an API token with only Zone → Cache Purge for the zone, stored as Convex env CF_PURGE_TOKEN with CF_ZONE_ID; then the cache rule. Claude can walk through it, or do it in Chrome, when this is built.
Saves
Most repeat egress and tunnel bandwidth; the box stops serving the same avatar to every device.

A4. Retire the home server

verifieddone 2026-11-06
Decided
Retired as a standby: it had been offline for weeks and missed every deploy since 2026-10-23. deploy.sh now deploys to the VPS only; --homeserver opts back in. This unblocks D1: no server needs the compatibility paths any more.

Phase B: server-only fixes (days, no app release)

B1. Stop the dismiss push on every "mark read"

verifiedserver-only
Now
markRoomRead always schedules notifications.dismissAndSync (messages.ts:3834), which runs a full _loadAlertTargets (~85 docs) to clear notifications on the reader's other devices. That was 21 of 33 push-target loads and 9.7 s of action time in the window.
Change
Skip when the reader has one live device (the reading device clears locally). Otherwise debounce: one dismiss per user per room per few seconds, keyed by a tiny pending row, and only when that room actually had an undismissed alert.
Saves
~64% of push-target loads; most of a reader's write-side cost.

B2. Receipt history as tiny rows instead of a rewritten array

verifiedserver-onlydecided 2026-11-06
Now
writeReceiptLog rewrites the whole entries array on every cursor move, for both the read and the delivered log (receipts.ts:68, cap 200 at receiptLog.ts:32): ~11 KB written per markRoomRead, the biggest write per call.
Decided
Keep the feature exactly: device-confirmed "delivered", and per-message "delivered at" and "read at" times. They set us apart from competitors.
Change
Each cursor move inserts one small row (roomId, userId, kind, at, clock, ~100 B) into a receiptMoves table, indexed [roomId, userId, kind, at]. The "seen by / delivered at" screen reads the moves around the message's time with a bounded range. Trimming keeps the same 200-move history: past 200 moves for a user in a room, each insert also deletes the oldest one (a point delete, not a rewrite). Backfill the current arrays once, then drop receiptLogs.entries.
Saves
~11 KB → ~0.2 KB written per read, with the same history.

B3. Typing reads only live rows

verifiedserver-only
Now
Both typing queries .collect() every indicator row in a room, including rows that stopped typing hours ago (clearTyping only zeroes a timestamp). getTypingUsers also runs lensFor, which scans all of the viewer's friendships twice plus guardianships, on every typing change.
Change
Index by_room_updated [roomId, updatedAt] and read .gt("updatedAt", now - TTL); replace lensFor with canSeeAs point reads for the 1 or 2 typists (the presenceApi.forUsers pattern).
Saves
Typing reads ~36 → ~3 per room, ~25 → ~4 per open room.

B4. Delivery receipts stop conflicting

verifiedserver-only
Now
advanceDelivered reads the room document (messages.ts:3912) only for memberCount and lastMessageTime, but every send patches it, so receipts arriving right after a send conflict (5 of 22). App and notification extension report the same message separately.
Change
Drop the room read (cap with Math.min(upTo, now), as markRoomRead does; the push signature already proves upTo). Later (B8) batch delivery server-side.
Saves
Conflicts to ~0; retries gone.

B5. Push targets in ~12 docs instead of ~85

verifiedserver-only
Now
Per recipient, _loadAlertTargets reads all devices and all sessions, and badgeTotalFor reads every membership, every room, unread messages per unread room, and every friendship pointing at the user to count pending requests (badges.ts:107-165).
Change
(1) A per-user userPushState row with live device tokens, rewritten only when devices or sessions change. (2) A per-user badgeState row: unread total and pending-request count kept at write time (R8). (3) Pass membership data from getMemberIds through instead of re-reading.
Saves
50-person group message: ~4,200 → ~600 docs.

B6. Friends, family and feed stop reading users

verifiedserver-only if shapes kept
Now
listFriends reads each friend's full users row and runs lensFor, re-scanning friendships three times (friends.ts:355). getMembers reads every member's users row (rooms.ts:701). feed:board reads each friend's users row (feed.ts:429). getFamilyContext returns children's status from users.
Change
Read profiles (and privacy flags copied there) instead; status comes from presenceApi:forUsers. Compute lensFor once and reuse it.
Saves
These re-run only on real roster or profile changes. Friends ~49 → ~25 docs.

B7. Small bounded-read fixes

verifiedserver-only
What
socialPush .collect()s all friendships and all of the author's moments per fan-out (socialPush.ts:598, 701, 864) → take() bounds. matches replays every move to get the board (matches.ts:1189) → store the current position on the match. Merge the two send rate buckets into one document (−1 write per send). files.repairRefs daily → weekly (its idle cost grows with the table).

Phase C: structural (backend, then one app release)

C1. Move cursors out of roomMembers

verifiedbreaking
Now
roomMembers mixes cold roster data (role, joined, mute) with hot cursors (lastReadAt, lastDeliveredAt, clocks). Every receipt re-runs, for every member, getReadState and getMembers (N rows each), and the owner's listUserRooms and getTypingForUser. The app even documents its own echo: a delivery report re-fires the list that triggered it (lib/data/chat_repository.dart:1432).
Change
A roomCursors table keyed (roomId, userId): read/delivered cursors, clocks, unread count, mention flag. send increments unread for members (the R8 trade: N tiny writes per send, replacing up to 100-message unread scans per room in every list run and push). markRoomRead writes only cursors. listUserRooms reads membership + room + cursor. getReadState reads only cursors. getMembers reads only roster + profiles. Backfill once.
Saves
estimate Chat list runs ~3 → 1 per incoming message; ~60 → ~30 docs per run; ~200 → ~60 ms. Roster queries stop re-running on receipts entirely. This is the biggest single win.

C2. Typing subscribed for visible rooms only, and paused in the background

verifiedbreaking
Now
The app subscribes getTypingForUser for every room for the whole session (chat_repository.dart:1331), never pauses it, and overlaps it with the open room's own typing query.
Change
Take roomIds (visible list rows, open room excluded), check access by point reads, and unsubscribe on app pause. Stop calling clearTyping: the indicator already expires, and the client can hide a typist when their message lands.
Saves
Typing runs 128 → ~20 per window; zero while backgrounded.

C3. Device-confirmed delivery, made cheap

verifieddecided 2026-11-06
Decided
"Delivered" stays device-confirmed (the phone really has the message), not "the push service accepted it". That is what makes the tick trustworthy.
Change
Keep one report per device, but make each one cheap: after B4 it reads no shared document and cannot conflict; after C1 it writes only the user's cursor row, re-running nothing but that room's "seen by" screen; the server ignores a report that doesn't move the cursor, so the app and its notification extension reporting the same message cost one write, not two. Optionally the extension skips its report when the app is in the foreground and already reported.
Saves
~4 reads and 2 writes with a 23% retry rate → ~2 reads and at most 1 small write, no retries, per device per message.

C4. Chat list payload and dedupe

verifiedbreaking
Change
Return only the fields ChatRoom.fromJson reads instead of spreading the room document. Store dmPeerId on DM rooms so the list stops scanning DM members (and stops re-running on the peer's writes). On the client, skip scheduleSaveRooms + notifyListeners when the payload signature didn't change (the pattern roomInvitations already uses). Split archived rooms into their own query.

C5. Sticker packs load lazily

verifiedbreaking
Now
expressions:packs collects every official pack and every sticker, with a URL lookup each: 567 docs in one call, subscribed.
Change
packs returns pack metadata; packStickers(packId) loads when a tab opens. Static data, so a plain query (not kept subscribed) is enough.
Saves
~99% of those reads.

C6. Thumbnails

verifiedbreaking
Change
The app uploads a 256 px avatar and a ~480 px preview next to each original (the box never resizes: no image work on 2 cores). Lists, bubbles and grids load the small one; full size only in the viewer. Pairs with A3.
Saves
estimate 90%+ of image bytes for lists and grids.

8. How to measure

Per-function cost from production logs

# Dump the server's log buffer (the CLI keeps tailing; stop it after a minute).
cd backend
npx convex logs --history 100000 --jsonl --success > /tmp/mh-logs.jsonl &
sleep 60; kill %1

# Aggregate: runs, docs read, docs written, time, conflicts, per function.
python3 -I - /tmp/mh-logs.jsonl <<'EOF'
import json, sys, collections
rows = [json.loads(l) for l in open(sys.argv[1]) if l.startswith('{')]
rows = [e for e in rows if e.get('kind') == 'Completion']
agg = collections.defaultdict(lambda: [0, 0, 0, 0.0, 0])
for e in rows:
    u = e.get('usageStats') or {}
    a = agg[e['identifier']]
    a[0] += 1; a[1] += u.get('databaseReadDocuments', 0)
    a[2] += u.get('databaseWriteDocuments', 0); a[3] += e.get('executionTime') or 0
    a[4] += 1 if e.get('occInfo') else 0
t = sorted(e['timestamp'] for e in rows)
print(f"{len(rows)} runs over {(t[-1]-t[0])/60:.1f} min")
for k, a in sorted(agg.items(), key=lambda kv: -kv[1][3])[:20]:
    print(f"{k:45} runs={a[0]:5} docs/run={a[1]//a[0]:4} writes={a[2]:4} "
          f"ms/run={a[3]/a[0]*1000:5.0f} occ={a[4]}")
EOF

9. Designs rejected

OptionWhy not
Bigger box or a second Convex instanceDoesn't remove the amplification; a 10× re-run problem costs 10× on any hardware. Revisit after Phase C.
Typing over a separate realtime service (WebSocket relay, Redis)A new moving part on a 2-core box. Bounded, visible-rooms-only typing in Convex (B3 + C2) is cheap enough.
Unread computed on read with a higher capExactly the scan-on-open pattern R8 forbids. Write-time counters (C1) cost N tiny writes per send, which already happen in spirit (every member's list re-runs on a send).
Server-side image resizingCPU on the scarce resource. The app already decodes images; let it upload the small variant (C6).
Aggregate "read by k of N" for every room size nowOnly needed for big groups; most rooms are DMs where read state is one row. Keep as an option if group sizes grow: above ~8 members, return the count and load the per-member list only when someone opens "seen by".
"Delivered" when Apple/Google accept the pushCheaper, but the tick would no longer mean the phone has the message. Rejected 2026-11-06: device-confirmed delivery and delivered-at times are a feature that sets us apart.
Third-party aggregate libraries (convex-helpers triggers)A dependency for something dbHooks.ts does in ~120 lines with a coverage test.

10. Decisions

Decided 2026-11-06

  1. Edge caching (A3): yes, with purge on delete. Privacy comes first: a deleted file must leave Cloudflare's cache within seconds.
  2. Delivered ticks (C3): stay device-confirmed, not "push accepted".
  3. Receipt history (B2): keep per-message "delivered at" and "read at" times at the same 200-move depth; only the storage changes (rows, not a rewritten array).
  4. Home server (A4): retired. deploy.sh is VPS-only by default.

Recommended order

  1. Phase A: A1 (mirror off), A2 (file reaper), A3 (cache + purge; needs the Cloudflare token).
  2. Phase B: B1 to B4 first (largest server-only wins), then B5 to B7.
  3. Phase C: C1 + C2 + C4 together in one app release; C5 and C6 can follow.
  4. Phase D once that release is the minimum version.
